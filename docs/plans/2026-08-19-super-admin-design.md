# 超级管理员审计与数据追溯设计

## 目标

在现有 Owner/Consumer 双角色系统上增加唯一的超级管理员，为其提供全局用户、数据流和策略管理能力，并将上传来源、查询、异常流量点与密文聚合说明串成可回溯链路。

## 方案

采用网关集中审计与追溯层。Spring Boot 网关负责唯一管理员认证、全局资源查询、高风险管理操作、审计落库和 CSV 数据点异常分析；Vue 管理控制台负责把资源、异常点、来源和计算步骤组合展示。底层加密服务保持不变，避免破坏旧架构兼容性。

超级管理员账号存放在现有 `custom` 表，身份为 `超级管理员`，业务上属于交通数据节点（Owner）的特殊分类。登录页不显示管理员入口；用户选择交通数据节点后，网关依据唯一账号自动识别并提升为管理员会话。启动时根据环境变量初始化，并删除同身份的其他账号，从数据库和注册入口两处保证唯一。普通注册接口不能创建管理员。

## 审计与追溯

新增 `admin_audit_log`、`user_account_status` 两张自动初始化表。审计表只提供读取接口，不提供删除接口。所有 `/api` 请求通过拦截器记录操作者、角色、方法、路径、结果、耗时、来源地址和追踪编号；管理员变更额外记录目标资源和动作摘要。

数据流详情将数据库元数据、Owner、Producer、上传状态、CSV 文件和策略关联起来。CSV 数据使用滑动窗口 Z-score 与相邻点突变率定位异常时间点。每个异常点返回时间、原值、局部均值、标准差、Z-score、突变率和原因。

## 密文聚合可观察性

管理页面展示授权校验、时间片切分、数据块统计、密文同态相加、边界钥片抵消、解密统计量和异常检测等步骤。真实可观测的来源、数量、时间和统计值标记为 `observed`；根据项目算法重建的公式与密文符号演示标记为 `derived`。页面不返回主密钥、派生密钥或可还原隐私数据的材料。

## 管理能力

管理员可以禁用/启用非管理员用户，删除任意普通策略、联邦策略和数据流，并重新计算选定数据流的追溯结果。删除数据流沿用关联记录清理逻辑，同时保留管理员审计记录。所有危险操作由前端二次确认。

## 验证

验证管理员唯一登录、普通角色隔离、用户禁用、全局列表、资源删除、审计不可删除、CSV 异常定位、追踪步骤字段，以及前端构建和网关编译。
